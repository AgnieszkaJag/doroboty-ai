# Synchronize local scenario tabs

## Problem and acceptance

After authoring the AI Product Manager demo, the user reported old content and different scores. The current displayed recruiter tab contained the saved 100/100 demo, while an earlier application tab still held only the two original project cards and an unsent form. The store read persistence only at mount and saved whole snapshots; a later action in that stale tab could replace the newer scenario.

Synchronize valid same-origin scenario changes into already-open tabs without writing them back. Refresh on window focus as recovery from a missed event. Before a domain action, check the latest persisted scenario; if a previously unseen update is adopted, reject that action with a clear retry message so a stale form cannot silently overwrite it. Preserve local unsaved state when storage fails or conflicting external data arrives, including corrupt-save blocking and export recovery. Explicit import/reset remain deliberate replacement operations.

Keep immutable application material and scoring unchanged. Verify the existing demo still contains the intended card/answer/CV and shows 100% overall/project in the user's tab after refresh. Add meaningful controller regressions for stale actions, valid external updates, corrupt data and storage failure; exercise two QA tabs with normal UI; run the required gate and a separate read-only review. Root is the sole writer.

## Implementation and verification

- `scenario-store.ts` owns the validated scenario snapshot, actions and persistence/recovery state. `store.tsx` subscribes with React's external-store API and attaches cleaned-up storage/focus listeners. External updates are read-only; invalid data preserves current memory and its raw recovery source. Unsaved local changes conflicting with a remote update block persistence and retain both copies for export. Import/reset retain their explicit replacement semantics.
- Seven new controller regressions passed: valid synchronization without writeback/repeated notification; a missed update rejecting the first action then preserving the remote application on retry; invalid external data and explicit recovery; quota failure plus concurrent data; unavailable storage; recovery after a valid replacement; and harmless invalid imports/propagated reset. No atomic multi-writer or cross-device guarantee is claimed.
- Manual two-tab CUA check on port 3002 passed: changed and confirmed criteria in the list, saw version 2 and the new criterion immediately in the already-open detail without reload, retained an unsaved recruiter note, then changed the stage in detail and saw the updated stage immediately in the list. QA tabs/server were closed afterward.
- In the user's actual displayed tab (CUA 26, native provider tab 25), refreshed and confirmed **100% overall / 100% project**, plus the new DEMO title, exact demonstrative answer and submitted profile material. The older tab (CUA 4) was also moved from its obsolete empty application form to the same current analysis, showing 100/100. Closed the earlier agent-only duplicate (CUA 25); the user's two tabs were retained. New proof capture: `artifacts/demo-ai-product-manager/confirmed-demo.jpg`.
- Separate read-only review passed with no material finding on subscription lifecycle, stale actions, corruption, dirty-memory conflicts and existing APIs. FEATURES SYS-09 and the brief now describe same-origin synchronization; the earlier milestone's no-sync statement is explicitly superseded.
- `./scripts/verify` passed formatting, immutable kit integrity/six kit tests, lint, TypeScript, **66 unit tests**, baseline verification and static build. All 44 browser cases failed before assertions because the provisioned Chromium headless shell is missing. The new two-tab E2E source is not reported as executed; the manual CUA evidence above is separate. Log: `/private/tmp/scenario-tab-synchronization-verify.log`.

Later diagnosis: the user's exact old record was in Chrome, with separate browser-local data. The stale-tab defect and its verified fix above do not synchronize separate browser profiles.
